# 실험 A: 기계 번역 참조 이름(T 조건) 설계와 분석 계획 (결과 보기 전 고정, 초안)

작성: 2026-11-13, GPU 실행 전. 결과를 본 뒤 바꾸는 부분은 날짜와 이유를 따로 적는다.
상태: **초안.** 아래 "정할 것"의 항목은 연구자가 결정한다. 독립 검토 전이다.

## 질문

R−O 이득(질문 속 참조 이름을 화면 언어 표기로 바꿨을 때의 정답률 상승)은 두 가지가 섞인 값이다.
하나는 이름이 화면과 **같은 언어**가 된 효과이고, 다른 하나는 이름이 화면의 **정확한 글자열**이 된 효과다.
T 조건은 이름을 화면을 보지 않고 기계 번역한 것으로 바꾼다. 언어는 화면과 같지만 글자열은 화면과 다를 수 있다.

| 대비 | 뜻 |
| --- | --- |
| T−O | 이름의 언어만 화면에 맞춘 효과 |
| R−T | 같은 언어 안에서 정확한 화면 글자열이 더하는 효과 |
| R−O | 기존 효과의 재현 |

T와 R은 둘 다 질문 본문 언어와 이름 언어가 섞인 질문이다. 따라서 R_stem/R_opts에서 문제가 됐던 혼합 표기 비용은 T−O와 R−O에 같이 들어가고, R−T에서는 상쇄된다.

## 입력 (이 맥에서 생성 완료)

- 문항·쌍: R_stem/R_opts와 같은 158문항(본 분석) × 불일치 언어쌍 12개 = 1,896쌍, 그리고 파일럿 12문항 48쌍. 입력 원본은 `rstem_ropts_qwen3_20261109/addon/followup_rel_4lang/rstem_ropts_inputs/mixed_conditions.jsonl`과 `rel_all_366/reference_mappings.jsonl`.
- 번역기: `mlx-community/gemma-3-12b-it-4bit` (revision `86cc6a8d…`), greedy, 화면 이미지 없이 텍스트만. 문항·원어·목표어마다 이름 목록을 JSON 배열로 한 번에 번역. 프롬프트와 원출력은 `work/translations_gemma*.jsonl`에 보존.
- 재번역: 1차에서 원어 그대로 남은 이름(원어 문자와 화면 언어 문자가 다른데 출력이 원문과 같음) 236곳과 출력 파싱 실패 묶음 1개(이름 3개)를 이름 하나씩 다시 번역. 그 뒤에도 원문 그대로인 곳은 27곳(main)이며 대부분 브랜드명이다. 그대로 둔다.
- T 생성: `build_T.py`. O 질문에서 R과 같은 위치의 이름을 번역으로 바꾼다. 같은 코드로 화면 글자를 넣으면 저장된 R 질문이 1,944쌍 모두 글자 단위로 재현됨을 확인했다.
- 출력: `work/T_gemma_conditions.jsonl` (1,944쌍), `work/T_gemma_spans.jsonl`, `work/T_gemma_report.json`.

## 실행 (GPU, 미실행)

- 모델: Qwen3-VL-8B-Instruct, InternVL3.5-8B. R_stem/R_opts와 같은 revision, 정밀도, 이미지 해상도, 프롬프트, greedy 최대 2토큰.
- 조건: O, T, R을 같은 실행에서 다시 돌린다. 한 쌍의 세 조건은 같은 배치에 넣는다(Qwen3 배치 3, InternVL3.5 배치 1). 기존 O·R 값은 재현성 확인에만 쓴다.
- 규모: 모델당 (1,896 + 48)쌍 × 3조건 = 5,832회. Qwen3는 R_stem 실행(7,584회, 약 99분) 기준으로 약 75분으로 추정한다. InternVL3.5 시간은 확인 필요.

## 주 분석

- 결과 변수: `generation_correct`. 보조로 `scoring_correct`.
- 분석 집합(제안): main 중 매핑 오류 쌍을 뺀 1,814쌍. 전체 1,896쌍 결과를 같은 표에 나란히 보고한다.
- 문항 i의 조건 c 정답률 p_i(c)를 그 문항의 남은 쌍 평균으로 둔다. T−O, R−T, R−O의 문항 평균을 %p로 보고한다. 문항 복원추출 10,000회(seed 20261113)의 95% percentile 구간을 붙인다.
- 주 대비는 T−O와 R−T 두 개다. bootstrap 부호 비율로 p를 내고 모델별로 Holm 보정한다.
- 강건성 GLMM: `correct ~ condition + query_language + gui_language + (1|item) + (1|pair)`, 기준 O. T와 R의 오즈비, R 대 T의 Wald 대비를 보고한다. 특이 적합이면 `(1|pair)`를 빼고 다시 적합한 결과를 함께 적는다.

## 보조 분석 (결론의 근거는 주 분석)

1. **실제로 다른 쌍:** R−T를 이름이 하나라도 "다름"인 쌍으로 한정한다(오류 제외 집합에서 1,695쌍, 157문항). 완전 일치 쌍은 정의상 R−T=0이라 희석을 막으려는 것이다.
2. **뜻이 보존된 쌍:** "다름"인 이름이 모두 번역-화면 LaBSE 0.7 이상인 쌍(684쌍, 143문항)의 R−T. 번역 오류가 아니라 글자열 차이만으로 R−T가 남는지 본다. 기준 0.7은 지금 고정한다.
3. **본문 이름이 다른 쌍:** 질문 본문 이름이 "다름"인 쌍(1,221쌍)의 R−T.
4. **화면 언어별** T−O, R−T. 태국어 화면을 따로 본다.
5. **민감도:** 불확실 매핑까지 제외, 주석 설명어 이름이 든 쌍 제외, 언어판 화면 간 숫자 표기가 다른 6문항 제외, 원어 그대로 남은 이름이 든 쌍 제외.
6. **설명 비율:** (T−O)/(R−O)와 bootstrap 구간. R−O의 구간이 0을 넘는 모델에서만 보고한다.

## 해석 규칙

| 결과 | 해석 |
| --- | --- |
| T−O > 0, R−T 구간이 0 포함 | 이득은 이름의 언어를 맞춘 데서 온다. 정확한 글자열이 더한다는 증거는 없다. |
| T−O 구간이 0 포함, R−T > 0 | 이득은 정확한 화면 글자열에서 온다(글자열 대조에 가까운 처리). |
| 둘 다 > 0 | 두 요인이 모두 기여한다. 비율은 설명 비율로 기술한다. |

- 구간이 0을 포함하면 "차이의 증거가 없다"로 쓴다.
- T의 번역 오류는 T 정답률을 낮춰 R−T를 키우는 쪽으로 작용할 수 있다. 그래서 "정확한 글자열 효과"는 보조 분석 2에서도 남을 때만 주장한다.
- "화면 글자"는 화면에서 직접 읽은 글자가 아니라 화면 언어판 질문의 이름이다. 논문에는 이렇게 적는다.
- 번역은 한 모델(Gemma 3 12B)의 결과다. 다른 번역기에서도 같은지는 이 실험이 답하지 않는다.

## 정할 것 (연구자)

1. 주 분석 집합: 매핑 오류 제외(제안)인가, 전체인가. 기존 R_stem/R_opts 보고와의 일관성도 함께 정한다.
2. 실행 모델: 두 모델(제안)인가, 한 모델 먼저인가.
3. 실험 B(위치 단서 상자)를 같은 실행에 묶을지.
4. 나머지 196문항 매핑 점검을 REL O/R/C/F 민감도용으로 할지.
