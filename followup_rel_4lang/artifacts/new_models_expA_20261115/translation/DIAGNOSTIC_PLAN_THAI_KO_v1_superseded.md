# 실험 A 진단 계획: 화면 언어에 따라 T−O의 방향이 갈리는 이유 (v1)

작성: 2026-11-14. Qwen3-VL-8B 결과를 본 뒤, InternVL3.5-8B 결과를 열기 전.
상태: v1. 초안(v0, `DIAGNOSTIC_PLAN_THAI_KO_v0_superseded.md`)을 독립 검토 결과에 따라 고쳤다. 고정 시각과 sha256은 이 파일 끝 "고정 기록"에 적는다. 고정 전에는 InternVL 예측 파일과 그 요약을 열지 않는다.

## 무엇을 봤나 (Qwen3-VL-8B, 사전 계획 분석, 1,895쌍)

| 화면 언어 | O | T | R | T−O (95% CI) | R−T | R−O |
| --- | --- | --- | --- | --- | --- | --- |
| en | 81.0 | 74.7 | 87.3 | −6.3 (−10.3, −2.3) | 12.7 | 6.3 |
| zh | 74.9 | 69.6 | 82.1 | −5.3 (−9.1, −1.5) | 12.4 | 7.2 |
| th | 47.7 | 66.2 | 81.6 | +18.6 (12.7, 24.5) | 15.4 | 34.0 |
| ru | 75.5 | 71.3 | 84.8 | −4.2 (−8.4, 0.0) | 13.5 | 9.3 |
| 전체 | 69.8 | 70.5 | 84.0 | +0.7 (−2.1, 3.4) | 13.5 | 14.2 |

화면 언어별 분석(sub5)은 사전 계획에 있었다(`DESIGN_ANALYSIS_PLAN_KO.md`). 방향이 갈린다는 해석과 아래 가설은 결과를 본 뒤 세운 것이다. 그래서 Qwen3 진단은 모두 탐색으로 보고한다. InternVL은 아래 사전 예측을 확인하는 자료로 쓴다.

InternVL로 확인되는 것은 "같은 문항, 같은 번역 입력에서 다른 모델로도 재현되는가"다. 문항이나 번역기와 무관하다는 뜻은 아니다. 또 두 모델이 같은 방향을 보여도 원인이 입력 쪽인지 모델 쪽인지는 가려지지 않는다. 두 모델이 같은 약점을 공유할 수 있기 때문이다.

## 입력 쪽에서 이미 확인된 것 (결과와 무관, `diagnostics_inputs_20261114/`)

- O 이름은 화면 글자와 거의 같지 않다. 정확 일치는 이름의 1.9%다(en 2.4, zh 1.4, th 1.9, ru 2.1). O의 글자 n-gram 겹침(chrF) 중앙값은 네 화면 언어 모두 0이다.
- T 이름의 화면 정확 일치는 화면 언어 간에 비슷하다(en 36.0, zh 38.2, th 35.5, ru 31.7%). 쌍 단위 정확 일치 증가량(`d_exact`)의 평균은 태국어 화면과 나머지가 같다(0.334).
- O에서 화면과 같던 이름을 T가 바꾼 경우는 19쌍(21개 이름)뿐이고, 모두 질문 언어가 영어다.

따라서 "화면과의 글자 겹침이 언어마다 달라서 방향이 갈린다"는 설명과 "T가 원래 맞던 글자를 깨뜨려서 떨어진다"는 설명은 입력 자료만으로 성립하지 않는다. 이 사실은 본문에 입력 쪽 결과로 적는다.

## 가설

H-A 원어 이름 연결의 붕괴 (주 가설). 화면을 보지 않은 번역(T)은 어느 화면 언어에서나 화면판 이름(R)보다 비슷한 만큼 모자란다. 달라지는 것은 O, 즉 모델이 원래 언어의 이름을 화면 글자에 스스로 잇는 능력이다. 이 능력이 태국어 화면에서만 크게 약해서 O가 T 아래로 떨어지고, 다른 화면 언어에서는 O가 T보다 높다. Qwen3에서 R−T는 12.4~15.4로 평평하고 R−O만 태국어에서 크다(34.0 대 6.3~9.3).

H-B 겹침의 용량-반응 (보조). 같은 화면 언어 안에서는 T가 화면과 더 많이 겹칠수록 T−O가 크다. 이것은 뒤집힘의 설명이 아니라 T 수준에 대한 설명이다.

H-C 번역 품질 (보조). 뜻이 틀린 번역이 T를 끌어내린다. 화면 언어 간 차이를 설명하려면 품질 문제가 en·zh·ru 목표 번역에 몰려 있어야 한다.

H-D 엇갈린 연결(near-miss, 보조). T 이름이 자기 화면 이름보다 같은 쌍의 다른 화면 이름에 더 비슷하면 모델을 다른 요소로 이끌 수 있다. 검토에서 해당 쌍은 화면 언어 간에 고르고(en 65, zh 53, th 62, ru 69), 효과도 양쪽에서 같은 방향이었다. 그래서 뒤집힘의 원인이 아니라 T 수준의 보조 요인으로 본다.

혼합 표기 비용(질문 본문과 이름의 문자가 다름)은 별도 가설로 두지 않는다. R도 같은 혼합 표기인데 모든 화면 언어에서 R−O가 양수다(+6.3~+34.0). 이 비용이 방향을 뒤집을 만큼 크다는 근거가 없다.

## 결과 지표

- 주 지표: `generation_correct`(지금까지와 같음).
- 보조 지표: 정답 확률 차(`gold_probability`, 원 척도, 조건 간 차이). 로그 척도는 쓰지 않는다. Qwen3에서 정답 확률이 0.999를 넘는 행이 47%이고 1e-6 미만도 54행 있어 로그 차가 꼬리에 좌우됐다(예: zh→th는 정답률 +15.2 pp인데 로그 차 평균은 −0.001).

## 확인 예측 (InternVL3.5-8B, 고정 뒤 확인)

대상은 사전 계획의 주 분석 세트(1,895쌍)이고, "나머지"는 en·zh·ru 화면 쌍 전부(1,421쌍)를 한 덩어리로 본다. 차이는 쌍 단위 정답 차를 해당 쌍들에서 평균한 값이다.

| | 예측 | 방향 |
| --- | --- | --- |
| P1 | 태국어 화면 T−O − 나머지 T−O | > 0 |
| P2 | 태국어 화면 T−O | > 0 |
| P3 | 나머지 T−O | < 0 |
| P4 | 태국어 화면 R−O − 나머지 R−O | > 0 |
| P5 | 태국어 화면 R−T − 나머지 R−T | 동등성: −5 pp ~ +5 pp 안 |

판정 규칙:

- 구간과 p는 문항 단위 군집 부트스트랩 10,000회(seed 20261114)로 낸다. 한 번 뽑은 문항 묶음 안에서 그 문항의 쌍을 모두 쓴다.
- P1–P4는 단측이다. 예측 방향이 ">0"이면 p = (1 + #{통계량* ≤ 0}) / (B + 1), "<0"이면 부호를 바꿔 같은 식을 쓴다. 네 p에 Holm을 적용하고(작은 p부터 α/4, α/3, …), α = 0.05(단측)다. 사전 계획의 양측 p와 섞지 않도록 표에 "단측"을 적는다.
- P5는 동등성 검정(TOST)이다. 부트스트랩 90% 백분위 구간이 [−5, +5] 안에 모두 들면 동등으로 판정한다. Holm 묶음에는 넣지 않고 따로 보고한다.
- 해석:
  - P1–P4가 모두 맞고 P5가 동등이면, H-A의 형태(뒤집힘은 O 쪽에서 생긴다)가 두 모델에서 재현된 것으로 적는다.
  - P2 또는 P3만 틀리면, 방향 차이는 재현되지만 부호 뒤집힘은 재현되지 않은 것으로 적는다.
  - P1이 틀리면, 태국어 패턴은 Qwen3에서만 관찰된 것으로 적는다. 이후 크기 축과 UI-TARS·MiniCPM 결과는 같은 코드로 기술만 한다.
- P4는 산술적으로 P1과 R−T 차이의 합이라 P1과 독립이 아니다. 같이 보고하되 따로 세지 않는다.

## 탐색 분석 (Qwen3와 InternVL에 같은 코드, 기술로 보고)

모든 구간은 문항 단위 부트스트랩 10,000회(seed 20261114), 양측 95% 백분위 구간이다. 탐색 분석에는 p값 보정을 하지 않고 구간만 적는다.

D1 셀 표와 정답 위치. 질문 언어 × 화면 언어 12칸의 O, T, R, T−O, R−T, R−O를 적는다. 정답 위치(A–D)별 T−O와 조건별 예측 라벨 분포도 같이 적는다. Qwen3에서 정답은 A가 42%이고, 나머지 화면의 T−O 음수는 정답 A(−8.8)와 B(−5.2)에 몰려 있다.

D2 화면 언어 안의 용량-반응 (H-B). 쌍 단위 T−O(정답 차)를 `d_exact`로 회귀한다. 화면 언어 고정효과(4수준)와 질문 언어 고정효과를 넣는다. `d_chrf`를 쓴 판을 따로 하나 둔다. 둘을 한 모형에 넣지 않는다(공선성). 화면 언어별 기울기도 적는다. "언어 간 차이를 설명한다"는 해석은 하지 않는다(`d_exact` 평균이 화면 언어 간에 같아서 구조적으로 불가능).
보조 예측(확인 아님): `d_exact` 계수 > 0. Qwen3에서 화면 언어를 통제한 계수는 +0.091(검토 시 1,000회 부트스트랩 [0.013, 0.163])이었다.

D3 겹침 없는 쌍 (H-A 보강). 사전 계획의 sub1(T 이름이 화면과 하나도 정확히 같지 않은 381쌍) 안에서 화면 언어별 T−O와 R−O를 낸다. 칸 크기를 같이 적는다. 태국어에서만 T−O가 양수이면, 화면과 같은 글자가 없어도 태국어 화면에서는 번역이 원어보다 낫다는 뜻이다.

D4 번역 품질 (H-C). 사전 계획의 sub2(뜻 보존, 708쌍)와 나머지 쌍으로 나눠 화면 언어별 T−O를 낸다. 목표 언어별 LaBSE(T 대 화면) 평균과 모델 판정 표본의 언어별 오류·부분 수를 같이 적는다.

D5 엇갈린 연결 (H-D). 정의: 이름마다 difflib `SequenceMatcher(None, a, b).ratio()`를 쓴다. a는 T 이름, b는 같은 쌍의 화면 이름이다. 둘 다 NFKC 정규화와 casefold를 한다. 이름 하나가 near-miss라는 것은 두 조건을 모두 만족한다는 뜻이다: 같은 쌍의 다른 화면 이름과의 최대 비율이 0.5 이상이고, 그 값이 자기 화면 이름과의 비율보다 크다. 쌍 안에 near-miss 이름이 하나라도 있으면 그 쌍을 near-miss 쌍으로 둔다. 화면 언어 × near-miss 여부별 T−O와 R 정답률을 적는다. R 정답률을 같이 적는 이유는, 이 쌍들이 원래 어려운 문항일 수 있어서다(문항 난이도와 섞임).

D6 사례 확인. 다음 네 묶음에서 20쌍씩 seed 20261114로 뽑는다.

- (a) en·zh·ru 화면에서 O 정답·T 오답
- (b) 태국어 화면에서 O 오답·T 정답
- (c) en·zh·ru 화면에서 O·T 결과가 같은 쌍 (a의 대조)
- (d) 태국어 화면에서 O·T 결과가 같은 쌍 (b의 대조)

판정자는 이름·번역·화면 글자만 본다. 어느 묶음인지와 모델 답은 가린다. 판정 범주는 미리 정한다: 번역 오류 / 번역은 맞지만 화면 용어와 다름 / 다른 요소 이름과 비슷함(near-miss) / 화면 글자와 같음 / 판단 불가. "일치를 깨뜨림"은 해당이 19쌍뿐이라 범주에서 뺀다. 판정자는 언어 모델이고 스크린샷은 보지 않는다(이미지 판정은 확인 필요).

D7 깨뜨린 일치 기술. `lost`=1인 19쌍의 T−O를 기술로만 적는다. Qwen3에서는 +5.3(lost=0은 +0.6)으로, 처음 예상과 반대 방향이었다. 검정은 하지 않는다.

## 배제한 대안 (Qwen3 검토 수치, 기술)

- 질문 언어 구성: 나머지 화면에서 질문 언어가 th일 때 −3.8, 아닐 때 −6.0으로 둘 다 음수다. 12칸 중 태국어 화면 3칸만 양수(+15.2~+20.9)다. 단 th 화면이 아닌 th→ru는 0.0이다.
- 매핑 오류 집중: 매핑 오류 쌍이 th 25, zh 26으로 비슷하고, 매핑 오류 쌍을 뺀 세트에서도 전체 결과가 유지됐다.
- 번역 충돌로 보기가 같아진 쌍: 1쌍(사전 제외)뿐이다.

## 정의 고정

- 정확·정규화 일치는 T 생성 코드(`build_T.py`)의 정의를 쓴다: 정규화는 NFKC + casefold + 앞뒤 공백 제거다. 입력 특성 README의 정규화 판정은 27개 이름에서 이와 다르다. 그 README 정의는 쓰지 않는다.
- `d_exact`, `d_chrf`, near-miss는 `diagnostics_inputs_20261114/per_pair_features.csv`와 이 문서의 D5 정의를 쓴다. chrF는 직접 구현이다(문자 n-gram 1–6, β=2, 공백 제거). sacrebleu와 같은 값인지는 확인하지 않았다(미검증).

## 하지 않는 것

- 이 진단을 위해 새 GPU 실험을 추가하지 않는다.
- 결과를 본 뒤 하위집단을 새로 만들지 않는다. 새로 필요해지면 날짜와 이유를 적고 탐색으로 표시한다.
- 화면 언어별 결과를 본문 주장으로 올릴지는 InternVL 확인 뒤 연구자가 정한다.
