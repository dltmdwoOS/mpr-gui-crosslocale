# 실험 A: 화면을 보지 않은 번역 이름(T 조건) 설계와 분석 계획 (결과 보기 전 고정, v2 초안)

작성: 2026-11-13, GPU 실행 전. v1(`DESIGN_ANALYSIS_PLAN_KO_v1_superseded.md`)을 독립 검토 결과에 따라 고쳤다. 결과를 본 뒤 바꾸는 부분은 날짜와 이유를 따로 적는다.
상태: 결정 반영본(2026-11-13). 연구자가 설계 판단을 위임했고, 아래 "결정 기록"의 선택은 그 위임에 따른 것이다.

## 질문

R−O 이득은 질문 속 참조 이름을 화면 언어판 표기로 바꿨을 때의 정답률 상승이다. T 조건은 같은 자리의 이름을 화면을 보지 않은 기계 번역으로 바꾼다.

| 대비 | 뜻 |
| --- | --- |
| T−O | 화면을 보지 않은 번역으로 이름을 바꾼 효과. 이름의 언어 일치, 우연히 화면과 같아진 글자열, 혼합 표기 비용이 함께 들어 있다. |
| R−T | 화면판 표기가 기계 번역보다 더하는 효과. 정확한 글자열과 번역 품질 차이가 함께 들어 있다. |
| R−O | 기존 효과의 재현 |

T 이름의 약 39%는 우연히 화면 글자열과 같다. 따라서 T−O를 "언어만 맞춘 효과"로 해석하지 않는다. 언어 효과에 가까운 추정은 보조 분석 1(화면과 같은 이름이 하나도 없는 쌍)에서 본다. T와 R은 둘 다 본문 언어와 이름 언어가 섞인 질문이므로 혼합 표기 비용은 R−T에서 상쇄된다.

- 출력 파싱 실패 1묶음(이름 3개)은 이름 하나씩 다시 번역했다(`work/translations_gemma_parsefail.jsonl`, sha256 `0433243b…`).

## 실행 (GPU, 미실행)

- 모델: Qwen3-VL-8B-Instruct, InternVL3.5-8B. 각 모델의 R_stem/R_opts 실행과 같은 코드(해시 대조), 설정 파일, revision, 프롬프트, 패키지 버전을 쓴다. greedy 최대 2토큰이다.
- 조건과 배치: O, T, R을 같은 실행에서 다시 돌리고, 한 쌍의 세 조건을 연달아 넣는다. Qwen3는 배치 3(한 배치 = 한 쌍), InternVL3.5는 배치 1이다. Qwen3는 기존 실행(배치 4)과 배치 구성이 달라 기존 O·R과 글자 단위로 같지 않을 수 있다. 기존 O·R 값은 재현성 확인에만 쓴다.
- 규모: main 1,896쌍 × 3조건 = 모델당 5,688회. 파일럿 48쌍은 돌리지 않는다(기존 R_stem/R_opts와 같음). 예상 시간은 Qwen3 약 75분, InternVL3.5 약 70분이다(기존 실행 실측 기준).
- 실행 묶음: `share_packages/expA_GPU_20261113/`. 이 안의 실행기 `run_rel_T.py`, 확인 기준 `check_T_gate.py`, 실행 스크립트 `run_expA.sh`, 안내서 `EXPA_RUNBOOK_KO.md`를 쓴다. 로컬에서 두 모델 모두 dry-run과 가짜 모델 실행(3문항, 전체 5,688회)으로 검사했다. GPU 실행은 미검증이다.
- 확인 기준(smoke 3문항 108회): 모두 성공, 배치 구성이 계획대로, 파싱 실패 2개 이하, 다시 돌린 O·R 답이 이전 실행과 Qwen3 90%·InternVL3.5 97% 이상 일치. 완료 기준: 5,688행 모두 성공, 파싱 실패 20개 이하.
- 무료 점검: T==R인 103쌍은 같은 실행 안의 같은 입력이다. 두 답이 다른 비율을 배치 내 수치 잡음 지표로 보고한다(Qwen3만 의미가 있고, InternVL3.5는 배치 1이라 같아야 한다). T==O인 쌍 1개(모든 이름이 원어로 남음)는 정의상 T−O=0이며 분석에 그대로 둔다.

## 주 분석

- 결과 변수: `generation_correct`. 보조로 `scoring_correct`.
- 분석 집합: main 1,895쌍(사전 제외 1쌍 제외). 기존 R_stem/R_opts 보고와 같은 기준이다. 점검으로 걸러낸 1,814쌍 결과를 같은 표에 나란히 보고한다.
- 분석 코드: `analysis/analyze_expA.py`(bootstrap, 모든 집합), `analysis/glmm_expA.R`(강건성 GLMM). 결과 전에 작성했고, 가짜 모델 출력으로 끝까지 돌아가는 것을 확인했다.
- 문항 i의 조건 c 정답률 p_i(c)는 그 문항에 남은 쌍의 평균이다. 제외 뒤 쌍 수는 문항마다 다를 수 있다.
- T−O, R−T, R−O의 문항 평균을 %p로 보고한다. 문항 복원추출 10,000회(seed 20261113)의 95% percentile 구간을 붙인다.
- p값은 bootstrap 부호 비율에 (1+개수)/(B+1) 보정을 한 양측값이다. 따라서 가장 작은 값은 약 2×10⁻⁴다.
- 주 대비는 T−O와 R−T이고, bootstrap 부호 비율 p에 모델 안에서 Holm 보정을 한다. 모델 간 보정은 하지 않는다.
- 두 대비는 T를 반대 부호로 공유하므로 음의 상관을 가진다. 그래서 같은 bootstrap 표본에서 (T−O)−(R−T)의 구간과 두 대비의 상관을 함께 보고한다.
- 강건성 GLMM: `correct ~ condition + query_language + gui_language + (1 + condition | item) + (1|pair)`, 기준 O. 수렴하지 않거나 특이 적합이면 `(1|item) + (1|pair)`로 내리고 그 사실을 적는다. T와 R의 오즈비와 R 대 T 대비를 보고한다.

5. **화면 언어별** T−O, R−T. 태국어 화면을 따로 본다.
6. **민감도**:
