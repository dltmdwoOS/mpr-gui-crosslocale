# 분석 규칙 v1 (고정, 2026-11-14)

상태: **고정.** 사용자 확인 후 고정했다. sha256은 `분석규칙_v1.FROZEN.txt`에 있다. 원래 초안 `분석규칙_초안.md`(2026-11-12)와 검토 전 후보 `분석규칙_v1_고정후보_r0_superseded.md`는 그대로 둔다.

## 0. 적용 범위와 시점

- 이 규칙은 Qwen3-VL-8B, InternVL3.5-8B 결과를 본 뒤에 썼다. 두 8B 모델에 대해서는 사전 규칙이 아니며 원고에도 그렇게 밝힌다.
- 사전 규칙의 대상은 고정 시점에 결과를 열지 않은 모델 전부다.
  - 현재 큐: Qwen3-VL-4B, InternVL3.5-4B, UI-TARS-1.5-7B, MiniCPM-V-4.5의 REL O/R/C/F와 실험 A O/T/R, 같은 네 모델의 6×6이다.
  - 큐 설정은 `ONLY="qwen3_vl_4b internvl35_4b uitars_15_7b"`, `MODELS="uitars_15_7b minicpm_v45 qwen3_vl_4b internvl35_4b"`다. 2B와 1B 모델은 돌리지 않는다.
  - 나중에 다른 모델을 돌리면 그 모델에도 이 규칙을 그대로 적용한다.
- 게이트를 통과한 모델은 결과와 상관없이 모두 보고한다.
- 큐가 진행하며 남기는 smoke 정확도 줄과 게이트 JSON의 정확도는 보일 수 있다.
  - Qwen3-VL-4B의 smoke 값은 이미 봤다. REL 0.54(80회), 실험 A 0.68(108회)이다.
  - 고정 전에는 `full_*_summary.json/csv`와 예측 파일을 열지 않는다. 결과 묶음은 내려받기만 한다.
- 실험 A의 진단 분석(`diag_expA.py`)은 새 모델에 같은 코드로 돌리되 "descriptive"로 표시한다. 확인 검정은 InternVL3.5-8B 한 번으로 끝났다. 새 모델에서는 en·zh·ru 화면 묶음의 T−O를 기술 지표로 함께 보고한다.

## 1. 주 지표

- 주 지표는 생성 답 일치(`generation_correct`)다. MPR-GUI와 같은 채점이다.
- 파싱 실패는 오답으로 채점한다.
- 레이블 확률 채점(`scoring_correct`)은 민감도 분석으로 함께 보고한다.
- 모델마다 다음을 표로 보고한다.
  - 두 지표의 일치율
  - 파싱 실패 수: 실험 묶음별, 조건별, 화면 언어별
- 생성 파싱 실패율이 2%를 넘는 실험 묶음은 따로 처리한다.
  - 분모는 그 실험 묶음(REL, 실험 A, 6×6 각각)의 성공 행이다.
  - 두 지표에서 주 대비의 부호와 Holm 판정이 같을 때만 본문에 쓴다.
  - 다르면 부록으로 보내고 그 사실을 밝힌다.

## 2. 태국어

- 어떤 모델도 태국어를 빼지 않는다.
  - 모든 분석에서 전체 언어 결과와 태국어 제외 결과를 나란히 보고한다.
  - 전체 언어는 REL과 실험 A에서 4언어, 6×6에서 6언어다.
- 주 판정은 전체 언어 결과로 한다. 태국어 제외 결과로 판정이 바뀌면 그 사실을 본문에 적는다.
- 읽기 지표는 해석 표시용으로만 쓰고 제외 기준으로 쓰지 않는다. 새 GPU 실행 없이 계산한다.
  - (a) REL R 조건 정답률: 태국어 화면 ÷ 영어 화면(전체 문항)
  - (b) 6×6 REL 차원(366문항): TH→TH ÷ EN→EN. 6×6이 있는 모델만 계산한다.
- 둘 중 하나라도 0.7 미만이면 표에 "태국어 화면 읽기 약함"으로 표시한다.
  - 모든 모델의 비율 값을 표에 그대로 적는다.
  - 표시된 모델의 태국어 결과는 언어 효과와 읽기 실패가 섞였을 수 있다고 적는다.
- 0.7은 사후 문턱이다. 8B 두 모델의 (a) 0.95/0.60, (b) 0.83/0.54를 본 뒤 정했고, 원고에 그렇게 밝힌다.

## 3. 주 대비와 다중비교

| 묶음 | 주 대비 | 판정 |
| --- | --- | --- |
| REL O/R/C/F | R−O, C−O, F−C, F−R | 모델별 Holm 4개 |
| 실험 A O/T/R | T−O, R−T (R−O는 보고만) | 모델별 Holm 2개 (사전 계획과 같음) |
| 6×6 | RQ1 GLMM의 matched 항 | LRT χ²(1), 한 개라 보정 없음 |
| 언어 방향·화면 언어별 분해, 크기 비교 | 전부 | 보정 없음, "탐색적" 표시 |

**REL**

- 주 대비는 의존 문항 층에서 계산한다. 제외 규칙은 8B와 같은 `prepare_glmm`이다.
- 독립 문항과 전체 결과는 보고만 한다.
- Holm에 넣는 p는 문항 bootstrap 10,000회의 부호 비율 양측 p((1+개수)/(B+1))다.
- seed는 REL 42, 실험 A 20261113이다.
- GLMM Wald p는 민감도 분석으로 보고한다.

**실험 A**

- 주 분석 집합은 1,895쌍이다(`rel::5/forest_9.jpg::zh::ru` 제외, 사전 계획과 같음).

**6×6**

- 주 대비는 8B 분석과 같은 RQ1 GLMM의 matched 항이다. 공식은 바꾸지 않는다.
  - 공식: `y ~ question_language + gui_language + dimension + matched_num + (1 | parallel_id)`, binomial logit, nAGQ=1
  - matched 항이 없는 기준 모델과 비교한다.
  - 코드: `analysis_internvl35_6x6_20261112/code_01/analysis/rq1_glmm.R`(sha256 0b587121…)와 `glmm_utils.R`(be906d33…)
- 판정은 LRT χ²(1)다.
- 효과 크기는 두 가지로 보고한다.
  - 문항 주변화 보정 확률 차(%p, MVN 2,000회 95% 구간)
  - OR
- 단순 차이는 민감도 분석으로 함께 보고한다.
  - 정의: 대각 6칸 평균 − 비대각 30칸 평균, 문항 bootstrap 10,000회
  - GLMM이 특이 적합이거나 수렴하지 않으면 그 사실을 적고 단순 차이를 본문에 함께 둔다.
- 태국어 제외는 5×5(en, zh, fr, ru, ja)다.

**공통**

- 앱 단위 bootstrap은 민감도 분석으로 부록에 둔다.

## 4. 모델 간 주장

- 모델 간 절대 점수는 비교하지 않는다. 주장은 모델 안의 조건 차이로만 한다.
- **재현의 정의:** 새 모델의 주 대비가 8B 기준 방향과 같은 부호이고, 그 모델 안의 Holm 보정 양측 p가 0.05 이하인 경우다.
  - 부호만 같으면 "부호 일치"로 센다.
  - 기준 방향은 R−O > 0, F−C > 0, R−T > 0, 6×6 matched > 0이다.
  - C−O, F−R, 4언어 T−O는 8B에서 방향이 정해지지 않았으므로 양측 추정만 보고한다.
- 분모는 게이트를 통과한 모든 모델이다.
- 모델 간 다중비교 보정은 하지 않는다. 대신 모델 수 × 대비 수만큼 검정했다는 사실을 밝히고 전체 표를 그대로 싣는다. 합동 검정은 하지 않는다.
- **크기 축:** 계열당 4B와 8B 두 점뿐이다. 크기 경향은 검정하지 않고 표와 그림으로만 보이며 "탐색적"으로 표시한다.
- **계보:** 이번 큐의 모델은 모두 Qwen 계열 언어 모델 위에 있다.
  - Qwen3-VL 4B/8B와 InternVL3.5 4B/8B는 Qwen3 언어 모델을 쓴다.
  - MiniCPM-V-4.5는 Qwen3-8B 언어 모델을 쓴다(확인 필요, 모델 카드 인용 전). 따라서 InternVL3.5-8B와 독립 표본이 아니다.
  - UI-TARS-1.5-7B는 config와 가중치 이름이 Qwen2.5-VL-7B와 같다. 이는 구조 확인일 뿐이고 미세조정 출처는 확인 필요다.
  - 그러므로 "여러 언어 모델 계열"이라고 쓰지 않는다. 비전 인코더와 학습 데이터가 다르다고만 쓴다.

## 5. 새 모델 포함 기준

- 큐 게이트를 통과한 모델만 본문 표에 넣는다. 게이트는 모든 행 성공, 파싱 실패 기준, 라벨 쏠림, A–D 확률 질량이다. 게이트에서 멈춘 모델은 부록에 이유와 함께 적는다.
- **시각 토큰 예산:** 모델마다 다르다. Methods에 모델별 값을 적는다.
  - MiniCPM-V-4.5는 576~640토큰이다.
  - Qwen3와 InternVL은 최대 약 2,048~2,304토큰이다.
  - Qwen3 계열 어댑터는 `visual_token_count`를 기록하지 않으므로 `prompt_token_count`로 대신 보고한다.
- **배치 크기:** 새 모델은 전부 배치 1이다. Methods에 다음을 적는다.
  - Qwen3-VL-8B의 실험 A는 배치 3, 6×6은 배치 4였다.
  - Qwen3-VL-8B를 배치 1로 다시 돌린 672회와 배치 4 답의 일치율은 98.66%(663/672)였다.
