# 위치 출력 형식 검토: v1→v2→v3

검토일: 2026-11-03. 기존 v1의 **0–1000 점 좌표를 두 모델에 공통으로 강제하는 계약은 사용하지 않는다.** 이 결론은 관련 모델의 1차 자료와 현재 저장소의 CPU 전처리 확인에 근거한다. v2 양성 대조 결과를 보고 Qwen 지시문만 v3로 수정했다. v3 O/R 파일럿은 게이트 실패로 실행하지 않았고, 별도 짧은 표현 진단의 탐색적 O/R 결과는 [파일럿 결과](QWEN_PILOT_RESULTS_KO.md)에 기록했다.

## 현재 저장소에 적용한 반례 검사

기존 Qwen 객관식 실험의 픽셀 예산(262,144–2,097,152)과 설치된 `qwen_vl_utils`/Transformers 전처리를 사용했다. `booking_en_1.jpg`는 원본 **1228×2700 → 중간 1232×2688 → 최종 980×2128**이며, 마지막 크기는 CPU에서 실제 `image_grid_thw=[1,152,70]`으로도 확인했다. 680개 GT 화면 전부 최종 높이가 1000을 넘고 172개는 폭도 넘는다. 전부 원본 크기와 최종 크기가 다르다.

모든 GT bbox 중심에 완벽한 **Qwen 절대 픽셀 점**을 가정한 반례 검사에서, v1의 0–1000 파서는 680개 중 **293개를 좌표 범위 밖으로 즉시 거부**했다. 나머지에서도 v1 방식으로 잘못 역변환한 점이 우연히 같은 GT 안에 들어간 화면은 **8개뿐**이었다. 이는 모델 성능 측정이 아니라 **채점 계약 오류의 계산상 반례**다. 좌표를 옳게 출력하는 모델도 거의 전부 오답이 될 수 있으므로 v1을 실행하면 안 된다.

## v2의 선택과 v3에도 남은 반증 가능성

- **같은 연구 질문·표본·O/R 조작을 유지**한다. 두 모델의 원시 점 정확도를 서로 비교하지 않고 각 모델 내부의 R−O를 본다. Qwen은 절대 픽셀 점, InternVL은 정규화 bbox의 중심을 원본 이미지 공간으로 옮긴다. 두 응답 방식의 난도가 다르므로 모델 간 R−O 크기 비교도 신중히 해석한다.
- Qwen의 `point_2d` JSON 배열은 공식 예시와 GUI 평가 선례에 맞지만, GUI referent를 찍는 유일한 최적 프롬프트라는 근거는 없다. InternVL도 공식 예시는 bbox이지 이 연구의 전체 질문 문장과 똑같은 입력이 아니다. **점 하나만 명확한 JSON 객체나 단일 객체 배열은 위치 채점에 사용**하되 요청한 배열 형식의 준수율을 따로 기록한다. 출력 추출 성공률과 쉬운 위치 대조를 파일럿에서 확인한다. 실패 시 본 분석 전에 버전이 표시된 **형식 수정**을 한다. O/R 이득을 보고 프롬프트를 고르지 않는다.
- 현재 `<ref>` 표시는 한 span만 바꾸려는 실험 조작을 정확히 표시한다. 그러나 `Locate the element named between <ref>...</ref>`라는 v1 문구는 `Phone Manager services`처럼 토글을 식별하는 **이름**을 토글 자체와 혼동할 수 있다. v3는 표시된 표현과 그 **주변 문장**이 묘사한 기준 요소를 질문보다 먼저 지정하고, 관계 질문의 정답 요소는 찾지 말라고 명시한다. 큰 영역 GT에 대한 기존 민감도 분석은 유지한다.
- Qwen의 최종 `image_grid_thw`, `qwen_vl_utils`가 만든 이미지 크기, 원본 이미지 크기, 렌더링된 프롬프트, 원시 출력을 각각 기록한다. 최종 크기를 프롬프트에 쓸 경우 프로세서가 실제 사용한 크기와 일치해야 한다. 이 일치 여부가 불명확하면 해당 입력은 실행하지 않는다.
- 큰 이미지의 다운스케일은 작은 GUI 대상의 성공률을 낮출 수 있다. 기존 객관식과의 연결을 위해 픽셀 예산을 그대로 두며, bbox 크기별 결과를 보고한다. 이미지 해상도를 바꿔 얻은 별도 결과를 잠금 O/R 결과와 합치지 않는다.

## 반증을 염두에 둔 판정

| 위험 | 관찰되면 어떤 의미인가 | 실행 전·파일럿 대처 |
| --- | --- | --- |
| Qwen이 원본·최종 입력 중 다른 크기의 좌표를 출력 | 픽셀 변환 후 오답이 생겨 언어 효과와 혼동 | 실제 `image_grid_thw`를 기록하고 쉬운 목표점과 원본/최종 좌표 가설을 대조한다. 좌표계를 정답에 맞춰 사후 선택하지 않는다. |
| `point_2d`가 아닌 설명·다중 점·bbox를 출력 | 위치 능력과 출력 형식 문제가 혼합 | 원시 출력, 단일 점 추출률, 요청 형식 준수율을 별도로 공개한다. 양성 대조·파일럿 게이트 미달이면 본 분석 전에 형식만 버전 올려 수정한다. |
| `<ref>`의 짧은 이름이나 관계 질문의 답을 찍음 | 모델이 기준 요소와 관련 UI 요소를 혼동 | 질문의 주변 단어를 함께 제공하고 답 요소를 찾지 말라고 지시한다. 파일럿 오류는 목표 단위와 관계 답 혼동으로 수동 분류한다. |
| InternVL bbox 중심은 맞지만 상자는 지나치게 큼 | point-in-box만으로 위치 지정이 좋아 보임 | bbox IoU와 bbox 크기를 보조 보고하고, Qwen 점과 InternVL bbox 중심의 원시 정확도를 직접 우열 비교하지 않는다. |
| GT가 토글보다 카드 전체를 포함 | 중심점 적중이 정확한 조작 대상을 뜻하지 않음 | 넓은 GT 8문항 제외 민감도를 사전 지정하고, 두 검수자 GT로 재채점한다. |

위 게이트는 **출력 계약의 기능 검사**이지 과학적 타당성 보증은 아니다. 특히 Qwen 공식 자료는 절대 좌표와 `point_2d` 사용을 뒷받침하지만 이 연구의 영어 지시문, `<ref>` 위치, 전체 질문 제공 방식까지 검증하지 않는다. InternVL 공식 형식도 bbox를 뒷받침할 뿐 동일한 질문 형식을 보증하지 않는다.

## v2 양성 대조 실패와 v3 수정

개인 캐시에 모델이 없어 최초 단건 시도는 토크나이저 로드에서 멈췄다. 이후 사용자가 파일럿을 요청하여 고정 revision의 소형 설정 파일을 받은 뒤, 공유 디스크에는 한 shard씩만 임시 저장하며 SHA-256 검증 후 GPU로 적재했다. 48개 파일럿 이미지의 입력 해시와 실제 전처리 크기를 확인하고 v2 양성 대조 **8건만** 생성했다. 원시 응답에는 네 숫자의 bbox 형태, 코드 블록 속 `point_2d`, 앞에 붙은 잡음, 잘린 JSON이 섞였다. v2 채점 계약에서 **8/8 파싱 실패**했고 사전 지정한 8/8 유효·6/8 적중 게이트에 미달했다. 따라서 v2 O/R 파일럿 **0/96**, 본 분석 **0건**이다. v2의 로컬 결과는 `results/grounding_pilot_qwen_v2/`에 따로 보존했다.

두 양성 대조 화면을 직접 보니 일부 좌표는 관계 질문의 **답 요소** 쪽을 가리켰다. v3는 모델의 [공식 예시](https://qwenlm.github.io/blog/qwen2.5-vl/)처럼 위치 지시와 이미지·질문을 **하나의 user 메시지**에 두고, 먼저 `<ref>`의 기준 요소를 지정한다. 답 요소를 찾지 말라는 지시를 질문보다 앞에 두었다. 채점하지 않는 `label` 생성은 제거해 긴 다국어 label 때문에 잘린 출력을 줄인다. 요청은 여전히 점 하나의 `point_2d` JSON 배열이며, 좌표계·표본·GT·O/R 조작·게이트는 유지한다. 이 변경은 **양성 대조의 기술 실패만** 근거로 했고, O/R 차이를 최적화한 것이 아니다. v3도 실제 양성 대조와 파일럿을 통과해야 사용 가능하다.
