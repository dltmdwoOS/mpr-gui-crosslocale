# RTX 4090 Qwen3 진단과 해상도 파일럿

고정일: 2026-11-05. 기존 Qwen3 파일럿의 프롬프트를 그대로 사용한다. 이 실험은
런타임 원인과 실행 가능성을 확인하는 탐색 진단이며, 실패한 v3 확증 실험을
재개하거나 그 결과에 합치지 않는다. 본 분석 158문항의 예측은 이 파일럿에 없다.

## 실행 계약

- Qwen3-VL-8B-Instruct revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`.
- Torch 2.9.1+cu130, Transformers 4.57.6, qwen-vl-utils 0.0.14.
- BF16, SDPA, greedy, 최대 64 새 토큰, 명시적 system 메시지 없음.
- 원본 `run_qwen3_prompt_pilot.PROMPT`와 원본 파일럿 12문항의 짧은 설명 유지.
- 0–1000 정수 점 하나만 유효. 원본 이미지 크기로 환산해 고정 GT 상자로 채점.
- 최소 픽셀 262,144, 최대 픽셀 2,097,152 / 1,048,576을 별도 계약으로 실행.
- 입력·프롬프트·GT·코드·라이브러리·메모리 배치 정책의 지문을 저장한다.

## 진단 순서

1. `booking_10` ZH→TH의 이미지 해시·격자·프롬프트 토큰 수를 과거 기록과 대조.
2. 기본 메모리 배치에서 2MP/1MP 및 배치 3/1을 측정. 추가 계측의 유무도 구분.
3. vision encoder를 patch embedding, 위치 임베딩, 27개 block, merger로 분해.
4. 실제 SDPA 첫 호출의 연산 경로를 기록. profiler가 GPU event를 주지 않으면
   event의 device time 0을 실제 GPU 실행 시간으로 읽지 않는다.
5. BF16 patch Conv3D의 native 경로와 `channels_last_3d`를 별도 조건으로 대조.
   Conv3D와 가중치 값은 유지하고 weight stride만 변경한다. 모든 이미지 패치의
   출력 오차와 전체 모델 좌표를 검사한다. bitwise 일치 여부와 수치 오차를 공개한다.

## 해상도 파일럿

해상도 파일럿을 시작하기 전에 위에서 확인한 메모리 배치 정책을 명시적으로 고정한다.
속도 개선을 기본 실행과 같은 런타임으로 간주하지 않는다.

- 같은 언어 대조: `booking_1`, `message_1` × EN/ZH/TH/RU × 전체 질문/짧은 설명.
  해상도별 16응답, 배치 1. 전체 질문은 목표 혼동을 확인하는 진단이다.
- 짧은 설명의 8응답 모두 유효하고 6개 이상 GT에 적중하면 해당 해상도의
  O/R/C 파일럿을 진행한다. 기존 기능 검사 기준을 유지한다.
- 파일럿: 12문항 각각 EN→ZH, ZH→TH, TH→RU, RU→EN의 4쌍.
  해상도별 48쌍 × O/R/C = 144응답, 조건 세 개를 배치 3으로 처리.
- 후속 본 실행의 기술적 기준은 O/R 96응답 중 90개 이상 유효 출력이다.
  C의 유효 출력·적중도 별도로 공개한다. R의 적중 이득을 통과 기준으로 삼지 않는다.
- 비교 지표: 생성 시간·CPU 준비·vision/언어 모델 시간·allocated/reserved VRAM,
  조건·GUI 언어별 유효률과 적중, 2MP↔1MP의 paired 정오 전환.
- 기존 B200의 같은 4쌍·12응답과 출력 문자열도 대조한다. 모든 신규 입력에 대해
  native 실행과 동등성이 확인됐다는 주장으로 확장하지 않는다.

12문항으로 1MP의 비열등성이나 R의 일반적 이득을 확정하지 않는다. 속도 문제가
메모리 배치로 해결되면 2MP를 본 실행의 우선 기준으로 유지하고, 1MP는 별도
민감도 설정으로 다룬다. prompt를 새 파일럿 정오에 맞춰 수정하지 않는다.

## 본 실행 준비

`run_qwen3_grounding.py`는 문항 단위 SHA-256 샤드와 계약 검증 후 재개를 지원한다.
`--suite main`은 고정 158문항 × 12 불일치 언어쌍 × O/R/C를 계획하며, 정확히
158문항·각 네 언어의 짧은 설명 파일을 요구한다. 파일럿 설명을 본 분석에 대신
쓰지 않는다. 설명은 해당 O/R/C 원문 질문의 연속 부분 문자열이어야 한다.

과거 `PROTOCOL_KO.md`의 전체 질문·Qwen2.5 좌표 계약과 통계 계획은 새 입력에
자동 적용하지 않는다. 본 분석의 설명·입력 잠금과 최종 통계 계획은 본 예측 전에
별도 버전으로 완성한다. GUI 상자의 넓이와 기존 annotation의 한계도 유지한다.
