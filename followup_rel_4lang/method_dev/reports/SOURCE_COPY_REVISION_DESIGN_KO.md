# Screenshot 직접 rewrite: 한 차례 수정 설계

이 설계는 기존 Screen 결과를 관찰한 뒤 정한 개발 실험이다. 추가 후보 sweep 없이 아래 프롬프트 한 개를 실행한다. 기존 코드·원시 출력·예측은 유지한다.

## 관찰과 가설

기존 완성형 rewrite는 171/240 정답이었다. 오답 69쌍 중 53쌍은 source annotation 바깥 문맥 보존 검사에서 경고가 나고 16쌍은 호환됐다. 정답에서도 121쌍에 경고가 있어, 문맥 번역을 오답의 원인으로 확정할 수 없다. 다만 선택적 정렬이라는 조작 자체를 위반하는 문제는 별도로 해결해야 한다.

Source 언어별 경고는 EN 4/60, ZH 53/60, TH 57/60, RU 60/60이다. 영어 예시 하나만 있던 프롬프트에서 비영어 문맥을 GUI 언어로 통번역하는 경향이 두드러졌다. 숫자 변화 11쌍, 보기 중복 3쌍도 관찰됐다. Source 문맥이 보존돼도 다른 화면 요소를 선택하거나 요일 정체성을 바꿀 수 있으므로 문자열 검사만으로 정렬 정확도를 판정하지 않는다.

## 이번에 바꾸는 것

`VISUAL_SOURCE_COPY_REWRITE`: 첫 지시를 원문 복사 후 최소 수정으로 바꾼다. GUI 언어는 이름에만 적용됨을 metadata 명칭에도 명시한다. 러시아어·태국어·중국어 원문 문맥을 그대로 두는 합성 예시와 영어 option 예시를 넣는다. 예시는 데이터셋에서 가져오지 않았다. 질문의 위치 관계를 따라가 답이나 이웃 요소를 교체 이름으로 선택하지 않도록 명시한다. 화면에 없는 distractor는 유지하고, 요일·월·날짜의 정체성을 바꾸지 않게 한다.

변환 입력은 screenshot, 원본 stem/A-D, source/GUI language뿐이다. Inventory, extractor, gold span, 정답, R/T target, 예측은 제공하지 않는다. 출력은 완성형 stem/options JSON이다. 모델에게 field/occurrence/edit metadata를 요구하지 않는다.

## 통제와 실행 범위

- Qwen3-VL-8B 동일 pinned revision, BF16, SDPA, seed42, 2MP image budget, 변환 batch1·출력768, 최종 batch3·출력2 유지.
- JSON 구조 실패에만 최대 한 번 repair, 이후 원문 fallback. 문맥·숫자·중복 검사는 생성 후 진단용이며 출력 거절에 쓰지 않는다.
- Screen288쌍 실행, main20문항×12방향=240쌍 주 분석, pilot48쌍 제외. Selection/Internal은 이번에 실행하지 않는다.
- 최종 입력의 전체 ordered batch가 기존 완료 배치와 일치하고 이미지 SHA·모델·seed·소프트웨어·GPU 지문까지 같을 때만 예측 재사용. 같은 입력에서 과거 출력이 충돌하면 재사용하지 않는다. 새 변환 프롬프트는 기존 변환 cache와 섞지 않는다.
- CPU mock 및 18개 표적 테스트 통과. 차원 기반 입력 추정 최대2980, repair 여유 포함3928<4096. 런타임에서는 실제 토큰·GPU 메모리를 재확인하고 초과 시 자동 truncation/배치 축소 없이 중단한다.

## 판단 기준

정확도와 함께 문맥 경고, 실제 수정 coverage, 원문 유지, 숫자 변화, 보기 중복, source/GUI 언어별 결과를 보고한다. 아무것도 바꾸지 않아 경고가 줄어드는 것을 성공으로 간주하지 않는다. O·이전 screenshot rewrite·inventory 기반 조건·R/F와 paired 비교하고 item bootstrap을 사용한다. 개선을 확인하기 위해 다시 프롬프트를 바꾸는 작업은 이번 실행에 포함하지 않는다.

나머지 138문항의 6–7시간 실행안은 새 결과와 실측 비용을 보고 제안한다. 아직 장시간 큐를 실행하지 않는다. 전체366문항으로 확장하지 않는다.
