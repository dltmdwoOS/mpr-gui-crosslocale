# Qwen3 실행 경로·출력 검증 보고서: RTX 4090

실행·정리일: **2026-11-05**. Qwen2.5-VL-7B-Instruct는 **Qwen2.5**, Qwen3-VL-8B-Instruct는 **Qwen3**로 표기한다. 이번 GPU 추론 대상은 Qwen3이며, Qwen2.5는 코드·설정·경로 선택만 추가 대조했다.

## 1. 핵심 판단

- **주된 지연은 패치 변환 Conv3D의 실행 경로였다.** 같은 2MP·배치 3에서 기본 경로 171.984초 → `channels_last_3d` 경로 2.421초, 한 배치 기준 약 **71배** 개선을 관찰했다.
- **동일한 모델·수학적 연산을 유지했지만 수치 출력은 bitwise 동일하지 않다.** 가중치 값은 같고, 메모리 배치와 실행 커널이 달라졌다. 최종 답변의 완전한 보존도 보장하지 않는다.
- **2MP를 우선 기준으로 유지한다.** 1MP는 빨랐지만 파일럿 적중이 줄었다. Qwen2.5의 과거 속도 원인, 개선한 B200의 성능, 4090 다중 GPU 처리량은 아직 확정하지 않았다.

## 2. 연구 질문과 이번 실행 범위

연구 질문은 **질문 속 기준 요소의 이름을 GUI 언어로 바꾸면 그 요소를 더 잘 찾는가**이다. 기존 객관식 REL 실험의 개선이 요소 찾기와 연결되는지 살피기 위해, 별도 위치 과제에서 기준 요소 안에 점 하나를 찍게 했다. 위치 과제의 개선만으로 객관식 추론 중 내부 grounding의 변화를 직접 증명하지는 않는다.

| 위치 조건 | 짧은 주변 설명의 언어 | 기준 표현의 언어 |
| --- | --- | --- |
| O | 질문 언어 | 질문 언어 |
| R | 질문 언어 | GUI 언어 |
| C | GUI 언어 | 질문 언어 |

예: EN→ZH에서 O=`blue '<ref>Search</ref>' button`, R=`blue '<ref>搜索</ref>' button`, C=`蓝色“<ref>Search</ref>”按钮`. 위치 과제에는 전체 객관식 보기나 F를 넣지 않았다. 객관식 REL의 O/R/C/F에서는 질문과 보기의 표현을 함께 조작한다.

| 수행한 검사 | 규모·역할 |
| --- | --- |
| 런타임 계측 | 2MP/1MP × 배치 1/3 × 기본/변경 경로 = **8배치·16응답** |
| 패치 출력 대조 | 같은 이미지의 **8,040패치·9,262,080개 출력값** |
| 같은 언어 대조 | 2문항 × 4 GUI 언어 × 전체 질문/짧은 설명 × 2해상도 = **32응답** |
| 불일치 O/R/C 파일럿 | 12문항 × 4언어쌍 × 3조건 × 2해상도 = **288응답** |
| 객관식 실행 점검 | 6×6 경로 **36입력**, REL **실제 추론 80개·조건 128행**, 별도 배치/단건 label 대조 **3+3응답** |

**전체 6×6·REL 재실행과 grounding 본 분석 158문항은 실행하지 않았다.** 파일럿 12문항은 본 분석에서 제외한다. 이번 [프로토콜](grounding_eval/QWEN3_RTX4090_PROTOCOL_KO.md)은 탐색 진단이며, 검증에 실패한 과거 v3 결과와 합치지 않는다.

재현 조건은 다음과 같다.

- RTX 4090 24GB, Python 3.12.15, Torch **2.9.1+cu130**, torchvision 0.24.1+cu130, cuDNN **9.13.0**, Transformers **4.57.6**, qwen-vl-utils **0.0.14**.
- Qwen3 revision **`0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`**, BF16, SDPA, greedy. 위치 과제는 명시적 system 메시지 없이 최대 64 새 토큰, 객관식은 기존 영어 system과 최대 2 새 토큰을 사용했다.
- 최소 픽셀 262,144, 최대 픽셀 **2,097,152 / 1,048,576**. 배치 3은 left padding이며 같은 화면도 조건마다 인코딩한다. 이미지 특징 캐시는 사용하지 않았다.
- `booking_10` ZH→TH는 과거와 이미지 SHA-256 `3f2fcbb5…`, 격자 `[1,134,60]`, 시각 토큰 **2,010개**, O/R/C prompt tokens **`[2131,2141,2129]`**가 일치했다. 전체 지문은 [입력 대조 기록](grounding_eval/rtx4090_20261105/rtx4090_booking10_2mp_preflight.json)에 있다.

## 3. 느린 경로의 원인과 변경 내용

기본 2MP·배치 3의 생성 171.984초 중 vision encoder가 **170.330초**, 언어 모델 첫 처리가 **1.011초**였다. 추가로 분해한 1MP·배치 3에서는 patch Conv3D만 **81.873초**, 뒤의 27개 vision block은 합계 약 **0.22초**였다. 11월 4일의 “전체 attention 계산량이 주원인일 수 있다”는 가설은 이 4090 지연의 주된 설명에서 제외한다.

현재 Torch 바이너리의 git revision `5811a8d7…`에는 **cuDNN 9.8 이상·9.15 미만의 일부 contiguous FP16/BF16 Conv3D에서 cuDNN 사용을 피하는 버그 회피 조건**이 있다. 현재 버전과 패치 커널이 이 조건에 해당해 `SlowDilated3d`가 선택됐다. `channels_last_3d`에서는 해당 제한 조건에서 벗어나 cuDNN 경로가 선택됐다. [바이너리에 대응하는 PyTorch 소스](https://github.com/pytorch/pytorch/blob/5811a8d7da873dd699ff6687092c225caffcf1bb/aten/src/ATen/native/Convolution.cpp#L394).

변경은 이미지 인코더의 **패치 Conv3D weight에만** 적용했다.

```python
model.model.visual.patch_embed.proj.to(memory_format=torch.channels_last_3d)
```

텐서의 논리적 shape·가중치 값·입력과 Conv3D의 수학적 정의는 유지하고, 물리적 저장 순서인 stride를 바꿨다. 해상도·모델 크기·BF16 설정을 줄여 얻은 개선이 아니다. PyTorch도 convolution weight의 메모리 배치를 바꿔 빠른 커널 사용을 돕는 방식을 설명한다. [메모리 배치 설명](https://docs.pytorch.org/docs/2.9/generated/torch.nn.utils.convert_conv3d_weight_memory_format.html).

**Qwen2.5의 과거 속도 원인은 별도로 남는다.** 두 모델 모두 패치 변환에 Conv3D를 쓴다. 같은 현재 환경에서 체크포인트에 맞는 형상으로 경로 선택만 검사한 결과는 다음과 같다.

| 형상 대조 대상 | 패치 커널·출력 채널 | 기본 배치 | `channels_last_3d` |
| --- | --- | --- | --- |
| Qwen2.5 | `2×14×14` · 1,280 | `SlowDilated3d` | cuDNN |
| Qwen3 | `2×16×16` · 1,152 | `SlowDilated3d` | cuDNN |

이는 [dispatcher 검사](grounding_eval/qwen25_qwen3_dispatch_20261105.json)이며 **Qwen2.5 가중치 적재나 전체 모델 실행은 아니다**. 과거 Qwen2.5가 빨랐던 이유를 두 모델의 고유한 기본 경로 차이로 단정할 수 없다. 당시 실제 cuDNN 버전·패치 weight의 dtype/stride·적재 경로 확인이 필요하며, 이번 4090 결과만으로 B200의 내부 경로도 확정하지 않는다.

## 4. 시간·메모리 측정과 해석

`generate`는 배치 전체의 생성 시간이다. CPU 전처리·모델 적재·설치·다운로드·결과 저장 시간은 포함하지 않는다. 모두 새 프로세스에서 모델 적재 후 첫 생성이며, `*`는 추가 profiler 또는 vision 세부 계측이 있다. 일반 계측에도 CUDA 동기화 타이머가 있다.

| weight 저장 형식 | 픽셀 상한 | 입력 배치 크기 | 생성 시간 | 최대 reserved VRAM |
| --- | ---: | ---: | ---: | ---: |
| 기본 | 2MP | 3 | 171.984초 | 18.492GiB |
| 기본* | 2MP | 1 | 60.143초 | 17.105GiB |
| 기본* | 1MP | 3 | 83.453초 | 17.525GiB |
| 기본* | 1MP | 1 | 29.973초 | 16.756GiB |
| channels-last* | 2MP | 3 | **2.421초** | 18.541GiB |
| channels-last | 2MP | 1 | 1.297초 | 17.176GiB |
| channels-last | 1MP | 3 | 1.764초 | 17.492GiB |
| channels-last | 1MP | 1 | 1.301초 | 16.766GiB |

같은 화면의 시각 토큰은 2MP의 **2,010개 → 1MP의 987개**로 줄었다. 이는 메모리 배치 변경과 구분되는 별도 입력 변경이다.

2MP·배치 3의 주요 구간은 다음처럼 변했다. 중첩 타이머이므로 각 행을 모두 더하지 않는다.

| 구간 | 기본 | channels-last |
| --- | ---: | ---: |
| 첫 model forward | 171.360초 | 1.864초 |
| 그 안의 vision encoder | 170.330초 | 0.865초 |
| 그 안의 언어 모델 첫 처리 | 1.011초 | 0.984초 |
| 후속 토큰 생성 forward 합계 | 0.453초 | 0.440초 |
| CPU 전처리 | 0.589초 | 0.561초 |
| 최대 allocated VRAM | 18.208GiB | 18.209GiB |

패치 연산 단독 대조도 기본 **57.838초 → 0.207초**였다. 메모리 용량은 기본 경로에서도 충분했으며, 개선 후에는 vision과 언어 모델 처리 모두 비용을 차지한다. 첫 SDPA 호출은 PyTorch 내장 Flash Attention 경로였고 외부 `flash-attn`은 사용하지 않았다. profiler의 GPU event 시간 0은 계측 한계이므로 실제 GPU 실행 시간으로 해석하지 않았다.

**71배는 같은 한 화면의 계측 비교**다. 최적화 쪽에는 세부 타이머가 더 있으며, 전체 과제의 반복 평균이나 Qwen2.5 대비 속도 비율은 아니다. 과거 B200 기본 경로의 161.289초와 이번 4090의 2.421초도 장비와 실행 정책이 함께 달라 직접적인 GPU 우열 비교가 아니다. [과거 런타임 보고서](QWEN_RUNTIME_REPORT_KO.md)의 64일/28일 외삽은 개선한 런타임의 일정에 적용하지 않는다.

## 5. 같은 연산과 같은 출력의 구분

메모리 배치 변경 전후의 **가중치 값은 완전히 같았다**. 그러나 같은 수학적 함수라도 서로 다른 커널의 연산 순서·묶음과 부동소수점 반올림 때문에 수치 출력은 달라질 수 있다. 이는 greedy 생성에서도 다음 토큰 선택을 바꿀 수 있다. [PyTorch 수치 정확도 설명](https://docs.pytorch.org/docs/2.9/notes/numerical_accuracy.html).

동일한 4090·이미지·패치 연산의 [직접 비교](grounding_eval/rtx4090_20261105/rtx4090_patch_embed_equivalence.json)는 다음과 같다.

| 비교 항목 | 결과 |
| --- | ---: |
| 비교한 출력값 | 9,262,080개 |
| 수치가 달라진 값 | 2,153,983개, 약 23.3% |
| 평균 / 최대 절대 차이 | 0.0002403 / 0.03125 |
| 참고 허용오차 검사 | `rtol=0.01, atol=0.01`에서 통과 |

허용오차 통과는 최종 정확도 동등성의 증명이 아니다. 차이를 개별 커널의 어느 반올림 단계가 만들었는지까지 분해하지는 않았다. 최종 응답에 대해서는 아래 범위만 확인했다.

| 비교 | 좌표 문자열 일치 | GT 적중 판정 일치 | 해석 범위 |
| --- | ---: | ---: | --- |
| 같은 4090의 `booking_10` O/R/C 변경 전후 | **3/3** | **3/3** | 같은 장비·한 화면의 직접 대조 |
| 과거 B200 ↔ 현재 4090, 불일치 4쌍 | 7/12 | 12/12 | GPU 차이도 있어 메모리 배치 효과만 분리 불가 |
| 과거 B200 ↔ 현재 4090, 같은 언어 대조 | 6/16 | 16/16 | 같은 제한; 전체 입력의 동등성 보장 아님 |

객관식의 별도 배치 3/단건 대조에서도 세 생성 label은 같았지만, label log probability 차이는 최대 약 **0.498**이었다. 따라서 모델 revision 외에 **메모리 배치·라이브러리·배치 크기도 실행 계약에 고정**하고, 기본/변경 경로의 결과를 같은 실행으로 합치지 않는다.

## 6. 프롬프트·해상도 파일럿 결과

EN/ZH/TH/RU 화면을 사용했다. 같은 언어 대조는 `booking_1`·`message_1`의 8화면이며, 같은 지시에서 입력 텍스트만 전체 관계 질문과 짧은 설명으로 바꿨다. 불일치 파일럿은 12문항마다 **EN→ZH, ZH→TH, TH→RU, RU→EN**을 사용했다. 네 언어의 모든 불일치 12방향을 실행한 것은 아니다.

채점은 **0–1000 정수 점 하나**만 파싱하고, 원본 이미지 좌표로 환산해 GT 상자 안인지 판정한다. 형식 실패도 오답이다. 넓은 카드 전체를 그린 GT는 작은 버튼의 정밀한 위치 지정과 구별해야 한다.

| 검사 | 2MP: 유효 / 적중 | 1MP: 유효 / 적중 |
| --- | ---: | ---: |
| 같은 언어 · 짧은 설명 | 8/8 · **8/8** | 8/8 · **8/8** |
| 같은 언어 · 전체 질문 | 8/8 · **0/8** | 8/8 · **0/8** |
| O | 48/48 · **40/48** | 48/48 · **36/48** |
| R | 48/48 · **45/48** | 48/48 · **43/48** |
| C | 47/48 · **38/48** | 48/48 · **34/48** |
| 배치 3 생성 중앙값 | **1.796초** | **1.050초** |

두 해상도 모두 짧은 설명의 양성 대조 기준과 O/R **96응답 중 90개 이상 유효** 기준을 통과했다. 불일치 파일럿 각 144응답은 모두 EOS로 종료했고 `addCriterion`은 없었다. 2MP C의 무효 1건은 괄호 없이 `490, 192`를 출력한 경우로, 사후 보정 없이 오답 처리했다.

- **목표 혼동은 남는다.** 전체 관계 질문에서는 기준 요소를 놓치고 짧은 설명에서 적중하는 양상을 재현했다. 답 요소의 별도 GT가 없어 정확히 무엇을 대신 찍었는지 단정하지 않는다.
- **R의 이득은 탐색적 관찰이다.** 2MP O→R은 오답→정답 7건, 정답→오답 2건으로 순증 5건이다. O/R 모두 유효 출력이어서 이번 차이는 형식 실패 차이로 설명되지 않는다.
- **1MP는 속도와 적중을 교환했다.** 2MP→1MP에서 O 4건 손실/0건 개선, R 2건 손실/0건 개선, C 5건 손실/1건 개선이었다.

GUI 언어별 적중도 균일하지 않았다. 각 셀은 **2MP → 1MP**, 분모는 모두 12다.

| GUI 언어 | O | R | C |
| --- | ---: | ---: | ---: |
| EN | 11 → 10 | 10 → 10 | 12 → 11 |
| ZH | 12 → 11 | 11 → 11 | 10 → 10 |
| TH | 7 → 5 | 12 → 12 | 6 → 3 |
| RU | 10 → 10 | 12 → 10 | 10 → 10 |

이 표본에서는 1MP 손실이 TH 화면에서 특히 눈에 띄지만 언어의 일반적 난도로 확정할 수 없다. **속도 병목이 해결된 현재는 2MP를 우선 기준으로 유지**한다. 12문항으로 해상도 비열등성이나 R의 일반적 이득을 확정하지 않으며, 48언어쌍을 독립적인 48문항으로 취급하지 않는다.

## 7. 본 실행 준비 상태와 남은 작업

**데이터:** 고정 source lock의 6차원(WF/WI/AU/AP/AEL/REL) 이미지·질문을 준비했다. 13,170 locale 행·2,195문항이며 대상 범위의 이미지 누락이 없다. RI/SI 이미지는 범위 밖이다. REL 이미지 1,464개·1,370,785,648바이트는 bundle SHA-256과 대조했고 같은 원본에는 hardlink를 사용했다. 구조·디코딩 감사와 680개 GT 이미지 연결 검사도 통과했다. 이는 의미적 정답의 독립 전수 검수가 아니며 기존 사람 검수 상태는 바꾸지 않았다.

**실제 러너:** 6×6 경로는 **한 REL 문항의 36언어 조합** 모두 성공·파싱 성공이었다. REL은 두 문항의 **80개 실제 추론 / 128조건 행** 모두 성공, 파싱 실패 0건이었다. 실행 가능성 점검이며 전체 6차원·모든 문항의 성능 검증은 아니다.

| 계획 작업 | 본 실행 규모 | 이번 준비 |
| --- | ---: | --- |
| Qwen3 6×6 | 2,195문항 × 36 = **79,020입력** | 8B 설정·계약·문항 샤드·재개, 생성 배치 1 |
| Qwen3 REL O/R/C/F | **23,424조건 행 / 18,432실제 입력** | Qwen3 배치·중복 입력 재사용·문항 샤드·재개 |
| 기준 요소 위치 찾기 | 158문항 × 12불일치 언어쌍 × O/R/C = **5,688입력** | main 러너·설명 초안·샤드·계약 후 재개 |
| **합계** | **103,140입력** | 과제 간 추가 중복 제거 전의 전체 계획량 |

8샤드 계획은 입력 ID 중복·누락 없이 분할했고 같은 문항의 언어·조건을 한 샤드에 유지했다. 이는 **계획 분할 검증**이며 다중 GPU 실측이나 생성 결과 병합 검증 완료를 뜻하지 않는다. 각 GPU에는 모델 한 벌과 서로 다른 입력을 맡긴다.

남은 연구 작업은 **158문항 × 4언어의 설명 632개 검토, 최종 입력 잠금, 새 과제에 맞춘 통계 계획 확정**이다. [설명 초안](grounding_eval/rtx4090_20261105/main_descriptors_draft_v2.json)은 모두 원문 부분 문자열이며 `reviewed=false`다. 자동 의문 표현 검사에 걸린 28개 후보를 수정해 현재 검출은 0개지만, 참조 이름만 남은 112개를 포함해 의미·문맥 검토가 필요하다. 과거 v3의 전체 질문·좌표 계약과 통계 계획을 자동 적용하지 않는다.

## 9. 실행 환경 논의: B200 또는 Vast.ai RTX 4090 1~8장

본 실행을 **메모리 배치 정책을 변경한 Qwen3로 연구실 B200에서 수행할지**, **Vast.ai의 RTX 4090을 1~8장 대여해 수행할지** 논의가 필요하다. 기존 B200 기록은 전체 카드가 아닌 **MIG `2g.45gb`·36 SM**이며, 변경 정책으로는 아직 측정하지 않았다. 현재 자료로 어느 장비가 더 빠르거나 경제적인지 결정할 수 없다.

결정 전 같은 고정 표본·2MP·메모리 정책으로 B200과 4090의 처리량·최대 reserved VRAM·출력 안정성을 비교해야 한다. 표본에는 grounding, 객관식 REL, 다중 이미지 WF를 포함하고 실제 B200 할당 범위를 확인한다. 이후 B200 가용 시간·자원 비용과 4090 대여료·저장/전송·준비 시간을 함께 비교한다. 4090 여러 장은 GPU별 독립 추론으로 확장하되, 공유 CPU/RAM/I/O와 샤드 불균형 때문에 8배 가속을 전제하지 않는다.
